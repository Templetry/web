# AGENTS

Operating contract for AI agents and automation helpers working in this project.

## Mission

- A React Router 8 application, **server-rendered on Cloudflare Workers**. The public pages are meant to be crawled; the server bundle is not an optimisation, it is the product.

## Core Rules

- **Never remove `main` from `wrangler.jsonc`.** The build goes green and produces no server bundle at all — a silent regression to client-only rendering that takes every page out of search with no error anywhere. `build/server/index.js` existing is the only proof that server rendering still works.
- Cloudflare bindings reach a loader through the typed context: `context.get(cloudflareContext)`. `AppLoadContext` was removed in React Router 8 and does not come back.
- `worker-configuration.d.ts` is generated by `npm run cf-typegen` and is not committed. If `Env` or `ExportedHandler` are unresolved, that is why.
- Unit tests run under `vitest.config.ts`, not the app's `vite.config.ts`. The app config installs the Cloudflare plugin and Vitest then tries to run node tests inside a workers runtime.
- Keep public routes and authenticated routes apart in `app/routes.ts`. It is what keeps the crawlable side light.

## Safe Change Workflow

1. Read the affected files fully before editing.
2. Make the smallest change that solves the task.
3. Build, then review the diff with git before committing.

## Required checks before finishing

```sh templetry:checks
npm run build
npm run typecheck
npm test
```

## This project came from a template

Four facts you cannot infer from the code in front of you:

- **Never hand-edit `.templetry-answers.yml`.** It records what generated this project. Editing it makes the next update merge against a state that never existed.
- **Before writing a capability by hand, run `templetry pieces`.** Auth, RBAC, audit trails, API keys and whole CRUD resources may already exist as pieces for this template. Adopting one is `templetry add <name>`, and it brings its own tests.
- **`templetry update` pulls improvements from the template** through a three-way merge that keeps your edits. Use it instead of copying files from the template by hand.
- **Directives like `tpl:if` belong to the template, not here.** If you find one in this project, it is a rendering bug worth reporting — do not try to interpret it.
